## Question guiding my learning

## My learning plan

Resources I will use:

- [WDD 231 Competency Guide](https://byui-cse.github.io/wdd231-course/resources/competencies/)
- [W3C WAI Page Structure Tutorial](https://www.w3.org/WAI/tutorials/page-structure/)
- [MDN: HTML as a basis for accessibility](https://developer.mozilla.org/en-US/docs/Learn_web_development/Core/Accessibility/HTML)
- [MDN: Accessibility tooling and assistive technology](https://developer.mozilla.org/en-US/docs/Learn_web_development/Core/Accessibility/Tooling)
- [WAVE Web Accessibility Evaluation Tool](https://wave.webaim.org/)
- [W3C Markup Validation Service](https://validator.w3.org/)

What I will build or practice:

I will build the home page for a personal portfolio in `projects/personal-portfolio/`. The page will include my face, my name, a short introduction, and a small list of projects I have participated in, along with the skills demonstrated by each project. I will structure the page with meaningful HTML and make its content and interactions understandable to keyboard users and assistive technology users.

Steps:

1. Plan the page content and identify the appropriate document structure, landmarks, headings, navigation, image description, links, and any controls before writing the page.
2. Write the home page HTML and add only the styling or setup needed to make the page readable and testable. I will write the assessed implementation myself.
3. Test the page with keyboard-only navigation, browser inspection tools, zoom or text enlargement, WAVE, and the W3C Markup Validation Service.
4. Record problems, hypotheses, changes, and verification results in `evidence/c01/`.
5. Prepare to explain my HTML decisions and demonstrate the page to a peer.

First milestone and due date: A working portfolio home page ready for keyboard, zoom, browser-tool, and WAVE checks by November 5, 2026.

How I will challenge my understanding:

Before testing, I will predict whether a keyboard-only user can move through the page in a sensible order, see where focus is, understand each link or control, and reach the main content without confusion. I will then test with `Tab`, `Shift+Tab`, `Enter`, and `Space`, inspect the document structure in browser tools, enlarge text or zoom the page, run WAVE, and validate the markup with the W3C Markup Validation Service. I will compare the prediction with the observed behavior and record any issue and its verification in my evidence notes.
