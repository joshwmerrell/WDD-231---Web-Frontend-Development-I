## Cross-cutting practice: Debugging and evidence-based troubleshooting

Use this practice in every contract and pass-off; it does not require a separate competency pass-off.

| Practiced | Evidence link or note |
| --- | --- |
| [ ] | Reproduce a problem and describe expected and actual behavior. |  |
| [ ] | Use console output, breakpoints, DOM inspection, network inspection, or incremental experiments. |  |
| [ ] | Form a hypothesis about the cause before changing code. |  |
| [ ] | Verify a fix and check that it did not create a regression. |  |
| [ ] | Explain what you would investigate next if the fix did not work. |  |

## Cross-cutting practice: Responsible AI-assisted learning

Use whenever AI is involved; it does not require a separate competency pass-off. AI may guide your learning but must not generate or complete code for the slices being assessed in your contract.

| Practiced | Evidence link or note |
| --- | --- |
| [ ] | Ask focused questions for explanations, objective clarification, hints, debugging hypotheses, or comparisons. |  |
| [ ] | Break large requests into smaller questions that you can evaluate. |  |
| [ ] | Check AI guidance against course materials, documentation, tests, experiments, and observed behavior. |  |
| [ ] | Reject suggestions that are incorrect, insecure, inaccessible, inappropriate, or would do the assessed work for you. |  |
| [ ] | Explain what assistance you used, what you accepted or rejected, and why. |  |
| [ ] | Explain the final work and identify which decisions and implementation are your own. |  |
